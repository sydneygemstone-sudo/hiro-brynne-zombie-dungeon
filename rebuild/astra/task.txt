核心范围 / Core scope

H-01 保留明确的地牢冒险闭环 / Keep a clear dungeon-adventure loop

保留第一人称、僵尸追击、战斗、剑、绷带、钥匙、地穴门、Boss、宝藏与逃生。

Retain first-person exploration, zombie pursuit, combat, sword, bandages, key, crypt gate, boss, treasure and escape.

验收 / Acceptance: 从开局正常找到钥匙并完成Boss与逃生；死亡与重开也必须可恢复。 / Normally find the key, defeat the boss and escape; verify defeat/restart recovery too.

H-02 按真实反馈修操作与节奏 / Repair controls and pacing from actual feedback

已有反馈包括迷宫太短、可互动少、朝向不对、速度太快；保留打击红色反馈与胜利时刻。

Existing feedback names short maze, too few interactions, wrong facing and excessive speed; retain hit feedback and the victory moment.

验收 / Acceptance: 使用同一设备比较移动、敌人朝向、攻击反馈与首次任务理解。 / Compare movement, enemy facing, hit feedback and first-goal comprehension on the same device.

H-03 合作要有作用，而非只在同一地图 / Cooperation must matter beyond a shared map

双人iPad合作是既有目标。新版先提出少量能被验证的合作选择；救援、分工或共享资源仍需课堂选定，不全量自动加入。

Two-iPad cooperation is an existing goal. Propose a small testable cooperative choice; rescue, roles or shared resources remain class decisions, not automatic additions.

验收 / Acceptance: 说明两个人怎样互相影响结果；单人模式仍能独立完成核心流程。 / Explain how two players affect the outcome while solo can still complete the core loop.

H-04 先改善决策与引导，再做完整资产 / Improve decisions and guidance before full assets

旧Hub指出重复“走路然后打怪”的问题。暗氛围、环境声和音乐是方向，但本阶段只需足够支持MVP，不擅自进入完整音画制作。

The old HUB identifies repetitive walk-and-fight play. Dark atmosphere/music/environment sound are directions; only MVP-supporting presentation belongs in this pass.

验收 / Acceptance: 玩家能指出一个有代价的选择及其反馈；正式故事、视觉、音乐、音效、配音留在第二阶段。 / A player can identify one meaningful trade-off and feedback; full story/art/music/sound/voice belong to phase 2.

Do not automatically add every roguelike upgrade, random map, shop or co-op mechanic; existing LAN play is not a deployed public multiplayer service.

What choices should recur between fighting, taking a detour, spending bandages and helping a teammate?
